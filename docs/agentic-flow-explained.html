How agentic-flow works

Start a plan in its own worktree, approve the brief, and let the controller coordinate implementation and review. The owner handles decisions and ships the reviewed branch.

Start and approve a plan

Run agentic-flow start <plan-id> from the project. It creates the plan branch, worktree and draft in docs/inprogress/. Use --type security for a Security plan. Draft the analysis and its implementation brief in that worktree, starting with the acceptance scenarios. The approved revision binds the steps and their verification commands. Merge base-branch updates into the plan branch to preserve that revision.

The owner approves the committed brief. For an approved plan that needs a clarification, commit the clarification first. agentic-flow approve <doc> --by <login> stages the updated approval for an authorized approver to commit.

scripts/plan-to-issues.sh --doc <doc>
scripts/plan-to-issues.sh --doc <doc> --apply

After approval, use the plan-to-issues skill. The dry run previews the generated work and --apply reconciles it on GitHub. Standard uses one work issue. Strict uses a tracker and a sub-issue for each step. Reapply after a clarification to update issue packets. The plan uses one branch and one PR, with one implementation commit per step.

Run the controller

agentic-flow run <doc> reads the approved plan and issue journals, selects the next station, and checks the station's result before recording it. Use agentic-flow run <doc> --once for a supervised turn. Unattended runs require distinct accounts, verified role credentials and validated station launch settings.

Executor

Implement a step

Read the packet, implement the step, run the prescribed checks and commit with Fixes #N. Return the full implementation SHA to the controller.

Reviewer

Review the submitted commit

Review the code and verification evidence against the approved brief. Return an approval or cite actionable findings tied to the submitted commit.

Owner

Resolve decisions and ship

Approve the plan, answer escalations and clear holds when resolved. Ship the reviewed plan and merge after final approval and CI.

The controller runs agentic-flow verify-step <sha> --doc <doc> --step <id> for the executor's commit. It checks the step's prescribed gates and recorded red-first checks where the brief requires them. The reviewer receives that verification record and can rerun a focused check to fill a specific gap.

In a manual session, use agentic-flow brief <doc> <step-id> to read the approved step and agentic-flow packet <issue> --station <role> to retrieve its station context. Manual stations verify and record their own handoffs with agentic-flow handoff <issue> <event> --as <role>. Under the controller, stations return result JSON and the controller records the handoff.

Read the journal and resolve andon

Authorized issue comments form the journal. It records transitions, evidence and the commit each verdict covers. Labels and issue state are derived from that journal. The controller also keeps a local ledger in the shared Git directory for station attempts, verification and recovery. Use agentic-flow handoff <issue> reconcile to repair issue projections or agentic-flow run <doc> --reconcile-only to reconcile the plan without launching stations.

Andon means the controller needs a human decision. It surfaces the reason in the issue and stops launches. Read the journal and the controller's diagnostic before resuming work.

  • A station's ask or a second review bounce escalates a step. The approver records the resolution with agentic-flow handoff <issue> resume --as approver --body-file <note> to return the step to its prior station. After an ask, the asking station's next packet carries the question and the approver's note under Owner decision, so the station acts on the answer instead of asking again. Only that station's latest ask since the last submit is carried, so a reviewer's question never reaches the executor. A long exchange is clipped in the packet, and the full text is delivered as decision.md in the station's scratch directory.
  • A plan hold, such as unexplained worktree changes, blocks further launches until cleared. Inspect the cause and any salvage reference. Use agentic-flow hold clear <doc> <hold-id> --note <text> after resolving it. Use --rebaseline only when intentionally accepting a changed worktree baseline.

Close out, ship and clean

  1. Once the steps are approved, complete the Tracker and Status fields and run agentic-flow close-out prep <doc>. Commit the staged move to docs/done/ or docs/done/security/ and the updated index. Do this before the first push: merging the PR without ship leaves the plan in docs/inprogress/ and needs a follow-up close-out PR.
  2. Run agentic-flow ship <moved-doc> --wait-review. It runs make ship-gate when defined, pushes the prepared head and opens or adopts the PR. A retry can reuse a passing gate for the same inputs and skips the push when the remote branch already carries the prepared SHA.
  3. After CI passes, the reviewer runs agentic-flow final-approve <moved-doc>. The final verdict identifies the PR head, CI run and attempt. ship finishes close-out, closes the plan's tracking issue and checks pre-merge readiness. To invoke that final close-out action directly, use agentic-flow close-out finish <moved-doc>.
  4. Merge the PR so the plan tip is reachable from the base. Run agentic-flow clean <plan-id> --dry-run to preview removal, then agentic-flow clean <plan-id> to remove the merged worktree and branch.

Station setup and harness maintenance

Use agentic-flow --help for command options and agentic-flow --version for the installed harness stamp.

CommandWhat it does
agentic-flow rolesShow station assignments. Use roles set, unset or manual to change how a station runs.
agentic-flow config explain <key>Show a setting's value, tier and source. Use config list for all settings.
agentic-flow doctor --stationsCheck station launchers and command policies before running the controller.
agentic-flow token <role> --checkCheck the configured GitHub identity for the executor, reviewer or approver.
agentic-flow metricsRead station timing, review bounces and andon counts from the local ledger.
agentic-flow statusShow the installed harness version, recorded source and pending merge candidates.
agentic-flow diffPreview the changes in a published scaffold revision.
agentic-flow upgradeApply the published payload and review any .agentic-new candidates. Use agentic-flow upgrade --merged <path> after resolving a candidate.
agentic-flow uninstall --jsonPreview which harness files are eligible for removal, what needs manual review and which preflight checks block removal.

Workflow rules and reference links are in the methodology. Setup and upgrades are covered in the adoption guide.
